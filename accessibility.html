Accessibility Statement

Our target, our current status, and an honest list of exactly what's not there yet.

WillIFit.ai exists to keep drivers from finding out the hard way that their vehicle doesn't fit. That only works if the site itself doesn't put up its own barriers. We're not there yet on every front, and this page says exactly where — the same way we label a clearance reading "imported" instead of dressing it up as verified.

Conformance target

We aim for WCAG 2.1 Level AA. Current status: partially conformant — most of the site meets that bar, and the gaps below are known, itemized, and not yet all fixed.

Target: WCAG 2.1 AA Status: Partially conformant Last reviewed: August 1, 2026

How this was assessed

This is a self-evaluation: an internal code review against WCAG 2.1, done by four focused passes covering semantic structure, keyboard and focus behavior, color and contrast, and page content — not a certified third-party audit, and not tested with real assistive-technology users. Automated and code-level review catches real, citable issues, but it can miss things only a person using a screen reader or switch device day-to-day would notice. If something here is wrong or incomplete, tell us — that's more reliable than any review we can do of our own code.

What's already solid

Not everything below is a problem. Some of this held up well under review, and it's worth saying which parts:

✓ A real focus trap on every modal — Tab and Shift+Tab wrap correctly, Escape closes the top one first, and focus returns to whatever opened it.
✓ A working skip link, one clear page heading, and a visible focus ring on every page — no components silently disable it.
✓ Body text contrast is strong throughout (15:1+ on the main text, 5:1+ on secondary text) — this was checked with real calculated ratios, not eyeballed.
✓ Reduced-motion, reduced-transparency, and increased-contrast preferences are all respected — most sites handle none of these.
✓ Every page has a language attribute, one clear heading, and a descriptive, unique title — across all 226 city pages, with zero exceptions found.
✓ No unlabeled images anywhere on the site, because the site doesn't use any — nothing to get wrong there.
✓ The garage-fit verdict in the detail panel is never color-only — it's always a plain-language sentence ("Won't fit — 4" too short").

Known issues

Grouped by area, most serious first. "Serious" means a real feature doesn't work for someone relying on that access method; "Moderate"/"Minor" are real but narrower or have a workaround.

Navigating and changing cities

  • Critical The city-picker's search results and state-browse list aren't operable by keyboard or announced to a screen reader — picking a city, the site's core action, currently requires a mouse. (WCAG 4.1.2)
  • Critical Status updates — result counts, load errors, "detecting your location," a report submitting successfully or failing — aren't announced to screen readers. They're silent unless you can see the screen. (WCAG 4.1.3)
  • Serious The four dialogs (city picker, both report forms, the add-a-location form) aren't marked as dialogs, so assistive tech doesn't announce a boundary or a title when one opens. (WCAG 4.1.2)
  • Serious Filter toggles ("Hide unverified," "★ Saved," garage/tunnel/bridge) don't expose on/off state — they sound identical either way. (WCAG 4.1.2)
  • Serious The city-picker's Search/Map/Browse tabs aren't marked as tabs, so their relationship to each other isn't conveyed. (WCAG 4.1.2)
  • Serious The min-clearance slider and the city search box rely on placeholder text instead of a real label, and the slider doesn't announce its value in feet — just a raw number. (WCAG 4.1.2, 3.3.2)

The garage detail panel

  • Serious When the panel is closed, its contents (Directions, Save, Share, both report buttons) stay reachable by Tab even though they're invisible — you can tab into content that isn't there. (WCAG 2.4.3, 2.4.7)
  • Serious Opening or closing the panel doesn't move focus in or restore it afterward — unlike every modal on the site, which does this correctly. (WCAG 2.4.3)
  • Serious One of the two image thumbnails ("Open Maps") is reachable by Tab but can't be activated by keyboard — its neighbor works fine, this one was missed. (WCAG 2.1.1)

Color and visual contrast

  • Serious The height badge and map-marker colors for "fits" vs. "tight" are almost the same brightness (a calculated contrast ratio of ~1:1 between them) — someone with color-vision deficiency likely can't tell them apart by color alone, and the badge itself carries no separate label. (WCAG 1.4.1)
  • Serious White text on the map markers' amber/green fills measures under 3:1 — below the minimum for that size text. (WCAG 1.4.3)
  • Serious The "Won't fit" label in the detail panel measures 3.94:1 against its background — just under the 4.5:1 minimum, on the single highest-stakes message in the product. (WCAG 1.4.3)
  • Serious Card, input, and chip borders measure well under the 3:1 minimum for UI boundaries site-wide — edges are present but very faint. (WCAG 1.4.11)
  • Moderate Links on the informational pages are distinguished from body text by color alone, with no underline until hover. (WCAG 1.4.1)

Page content and data tables

  • Serious Every AI-verified entry on all 226 city pages links the words "Google Street View" to our own methodology page instead of Street View itself — the link text names a destination it doesn't go to. This is a single template fix that corrects all 226 pages at once, and the highest-leverage item on this whole list. (WCAG 2.4.4)
  • Serious The data tables on the clearance guide and the Lowest Bridges page have header cells but no scope attributes — a screen reader reads each row as a list of bare values with no column association. (WCAG 1.3.1)
  • Serious The "will it fit" comparison table on the clearance guide conveys its verdict by text color only, and the legend explaining it is itself written in terms of color. (WCAG 1.4.1)
  • Serious The Lowest Bridges table scrolls horizontally on narrow screens, but that scroll region isn't reachable by keyboard — the City column is unreachable without a mouse or touchscreen at that width. (WCAG 2.1.1)
  • Moderate No page has a <main> landmark, including all 226 city pages — headings still make the page navigable, but landmark-based navigation (how many screen reader users jump around a page) doesn't work. (WCAG 1.3.1)

What we're doing about it

These are logged, prioritized, and not all fixed yet — we're not going to claim otherwise. The two Critical items (city selection, and silent status updates) are the current priority, since they block a core function rather than degrade it. We'll update this page as issues close, not just add new ones.

Report a problem

If you hit an access barrier anywhere on the site — something above, or something we missed — we'd genuinely rather hear about it than not:

  • Open an issue on our public GitHub repo — the fastest way to reach us directly, and you can see exactly what's already tracked.
  • Or use the Report an issue button on any garage's detail panel in the app — it reaches the same review queue as a data correction.
