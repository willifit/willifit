# WillIFit.ai — keyword / AEO audit

Compiled 2026-09-10. Methodology: live WebSearch queries (Claude's web search, US results) run one at a time; no Ahrefs/Semrush/Similarweb or other SEO tool is connected to this session. Every volume label below is an **estimate** based on: query genericness/breadth, how many independent commercial and content sites already target it, how often it recurs across forums (Tripadvisor, iRV2, TruckersReport, Reddit-adjacent), and (for local queries) city population/RV-tourism relevance — not on any keyword-volume tool. Difficulty is based on who actually occupies page-1 results for that exact query in this session's searches — named below per cluster — not a Domain Authority score. I could not directly observe Google's AI Overview panel: WebFetch on a live google.com/search URL returned only an access-blocked stub, not rendered results (confirmed by testing it once). The AEO section instead infers likely-cited source types from which pages/domains recur across organic results for related queries, and says so explicitly rather than claiming direct observation.

## Competitors

Four to six sites/apps that most overlap with WillIFit, based on what actually showed up repeatedly across every cluster searched this session:

**1. Low Clearance Map (lowclearancemap.com) + HeadRoom app**
Has: 26,000+ verified low-clearance bridges/tunnels across US, Canada, UK; directional "Hazard Heading" alerts (fires only in your direction of travel); a companion turn-by-turn nav app (HeadRoom, $4.99/mo, iOS + Android + CarPlay/Android Auto); a public API and a downloadable POI database sold on Gumroad; an active blog.
Lacks vs. WillIFit: no parking-garage coverage at all (bridges/tunnels only — no equivalent to WillIFit's 8,258-garage dataset); no AI/Street-View-verified heights (their claim is DOT-record + computer-vision + driver-feedback validation, a different verification method, not signage-reading); no per-city landing pages for browsing/SEO the way WillIFit's 226 city pages work.

**2. FindLowClearance.com**
Has: 18,000+ bridges/tunnels, US + Canada, a "near me" page pattern.

## AEO — what gets cited, and how WillIFit gets citable

Caveat restated: I could not load Google's actual AI Overview panel (WebFetch on a live google.com/search URL is blocked server-side — confirmed by testing). The patterns below are inferred from which domains/page-types repeat across organic results for each query and its close variants, which is the standard proxy for likely AI Overview / featured-snippet source material, not a direct observation. Flagging that distinction because Dan's stated preference is to flag exactly this kind of confidence gap rather than assert something as observed fact.

**1. "parking garage clearance height"** — Likely-cited source types: building-code aggregators (up.codes) for the numeric standard, towing/dealer blogs for the practical framing. What would make WillIFit citable: an answer-first sentence in plain text within the first ~40 words of the page body (not just the H1) stating the two numbers together — e.g. "Most U.S. parking garages post 7'0" to 8'2" of clearance; the ADA minimum for van-accessible spaces is 8'2" (98 inches)." — followed immediately by the sourced table. The existing page already has this shape; the fix is making sure the direct-answer sentence is literally the first paragraph, not buried after navigation/tool UI.

**2. "how tall is a u-haul truck"** — Likely-cited source types: U-Haul's own per-size pages (highest authority, but fragmented — no single U-Haul page answers "all sizes"), which is exactly the gap a well-structured third-party comparison table can fill for an AI answer that wants one citation covering every size. What would make WillIFit citable: a single table with one row per U-Haul size, the literal words "Clearance Height" in a column header (matching U-Haul's own terminology so an AI system can confirm your number against theirs), and a per-row anchor (`#uhaul-26ft`) so an answer engine can deep-link to the exact row instead of the whole page.

**3. "lowest bridge in america"** — Likely-cited source types: Wikipedia (for the structural-height meaning) and boating-community sites (for the Great Loop waterway meaning) — both answering a different question than WillIFit's page. What would make WillIFit citable for the *road-vehicle* meaning specifically: make the page's opening sentence explicitly disambiguate ("This is the lowest posted clearance for road vehicles, not the tallest/shortest structural bridge") so an answer engine parsing multiple "lowest bridge" pages can correctly attribute WillIFit's number to the road-clearance question rather than discarding it as off-topic. The existing page already states the number and a date ("updated 2026-09-01") up top — good; add the one disambiguating sentence.

**4. "eisenhower tunnel height limit"** — Likely-cited source types: CDOT's own official page (highest authority for the current 13'11" figure) and the 2007 history fact (Colorado Transportation Commission raised it from 13'6"), which recurs because it's a clean, memorable, quotable historical detail. What would make WillIFit citable: pairing the current number with that same kind of quotable, dated historical/context fact for WillIFit's own tunnel entries generally — a bare number is easy for an AI system to source from the official DOT page instead of a third party; a number *plus* a distinguishing fact (verification date, "AI-verified from Street View on [date]," a note about a recent change) gives an answer engine a reason to prefer citing the aggregator over the primary source for the "why" part of the answer.

**5. "class c rv height"** — Likely-cited source types: storage-company blogs (neighbor.com, recnationstorage.com) — currently winning because they're structured as direct-answer content (range up front, then caveats), even though their business purpose (sell storage space) is unrelated to the query. What would make WillIFit citable: match that direct-answer structure (range first, in the first sentence, feet-and-inches) but add the one differentiator storage blogs can't: a live link from the stated range straight into "RVs this tall won't fit under these bridges/garages" — i.e., make the page's answer functionally useful in a way a citation-generating AI system would want to point to as the more complete source.

**6. "bridge strike"** — Likely-cited source types: federal/academic sources (National Academies Press, ASCE) for statistics and definitions, specialist blogs (lowclearancemap.com) for the cost-per-incident framing ("$18,277 per incident" recurred from an NY State DOT-adjacent source). What would make WillIFit citable: if WillIFit publishes anything on this topic, cite the same NY State 2024 strike-count figure (350 strikes) and the per-incident cost figure with their original sources rather than re-deriving new numbers — an answer engine cross-checking multiple pages for the same stat is more likely to cite a page whose numbers agree with the federal/state source than one with a different, unsourced number.

**General page-structure recommendations that apply across all six** (based on comparing what currently wins vs. what WillIFit's existing pages already do well or are missing):
- **Answer-first sentence**: the literal answer, in plain language, within the first paragraph of body text — not just implied by the H1 or buried in a table. Confirmed present on `/parking-garage-clearance-heights.html` and `/lowest-bridges-in-america.html`; should be the template for any new page.
- **Heading forms as questions**: WillIFit's existing FAQ headings ("How tall is a standard parking garage?", "Will my RV fit in a parking garage?") already match natural-language query phrasing well — keep this pattern for the new vehicle-heights page (one H3 per vehicle: "How tall is a 26' U-Haul truck?").
- **Tables over prose** for anything comparative (vehicle sizes, garage types, state-by-state) — confirmed this is already the pattern on the existing garage and bridges pages; extend it to the new vehicle-heights page rather than writing it as narrative paragraphs.
- **Explicit dates**: the bridges page's "updated 2026-09-01" is a good signal and should be replicated on every new/edited page — AI systems and Google both appear to weight recency signals for these safety-adjacent factual queries, and none of the third-party competitor content (dealer pages, storage blogs) show a visible update date.
- **Per-entity anchors**: confirmed the Las Vegas city page already lists individual properties (Aria, Bellagio, MGM Grand, etc.) — verify/add stable per-property HTML anchors so specific entries are directly linkable and citable, not just findable by scrolling a long page.
- **Source-match terminology**: use the exact wording each source vendor uses ("Clearance Height" for U-Haul/Budget, "Overall Height" for Ford/Mercedes-Benz) rather than normalizing everything to one WillIFit-house term — this makes it easier for a fact-checking answer engine to match WillIFit's number against the primary source's own words, which is a real citability signal distinct from just having the correct number.
